# v0.0.1 / 4121c06e

Linux and U-Boot now share `fwctl help`, `fwctl capabilities` and
`fwctl factory-init a|b --force`. Help/capabilities do not open firmware storage.
Unforced factory requests fail before opening it; the old `init a|b` spelling is
removed. Linux `fwctl init` remains the no-argument initramfs PID 1 entry.
U-Boot human component/package versions now use vMAJOR.MINOR.PATCH.

Validation: eight native firmware/CLI groups, 36 automatic-upgrade and eight
boot-health cases; 11 U-Boot metadata tests; real sandbox factory operations and
unforced/legacy refusal with byte-identical metadata; four FIT tests, actual
AArch64 loader and Linux/U-Boot identity interoperability.

AM625 publication 63 rebooted and reported success. Real Linux refused both
unforced and old factory commands without changing metadata. Separate bootloader
maintenance then executed the new A53 SPL/U-Boot B, verified its capabilities,
refused those commands without changing metadata, and booted/confirmed Linux.
Direct reads matched all three new B payloads; the complete A boot partitions
matched their pre-maintenance backups throughout. Factory initialization with
force was tested only on disposable sandbox media, not on the running board.

Final running deployment 0 uses bootloader B, kernel/rootfs A, tag v0.0.1 and ID
`4121c06e23ebafd3dea627d72b09fe7fbcc15b42bcec92e5832e179edd3e8955`.
ROM still executes the preserved original R5 A; new R5 B was built and read back,
not executed by ROM. Old A53/U-Boot A still needs the documented controlled boot
for HWID-only firmware; this stage does not claim automatic A compatibility.

Evidence: `output/ota-validation/0.0.1-upgrade-08-command-contract/`, including
source fingerprints/archive, normal OTA and separate maintenance serial logs,
factory rejection snapshots and direct partition hashes.
