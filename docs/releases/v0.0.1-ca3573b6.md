# v0.0.1 / ca3573b6

The documented `fwctl update COMPONENT SOURCE` form now works. Invalid argument
combinations fail before opening firmware storage. Single-component updates
preserve earlier READY components and always choose the physical slot opposite
the confirmed source, including a repeated update of the same component.
Absent components and prohibited bootloader requests fail before metadata changes.

Physical updates require the actually booted deployment to be the confirmed
active source. Each block payload write holds an exclusive kernel partition
claim through direct readback, rejecting mounted partitions and device-mapper
holders. WRITING candidates cannot be manually confirmed.

Validation: seven native firmware/CLI/health/direct-read groups, 36 automatic
upgrade cases, eight boot-health cases, four real FIT tests, actual AArch64
initramfs loading and Linux→U-Boot→Linux metadata interoperability.

AM625 publication 61 reported success after reboot on device
`1c-63-49-22-c4-f7`. Before confirmation, a manual update was refused with EBUSY.
Subsequent maintenance tests staged kernel twice and rootfs into B, verified
that the running A image still matched its full physical SHA256, refused a
mounted standby write, and rejected confirmation of the WRITING candidate.
The complete package then re-established its aggregate identity, rebooted into
deployment 0 / kernel-rootfs B, passed health and directly matched both payloads.

The poller was stopped for manual maintenance to avoid its read checks competing
for the nonblocking storage lock; it restarted normally on reboot. No partition
geometry, primary bootloader or metadata format was changed.
