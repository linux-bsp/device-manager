# v0.0.1 / cf647820

Completed download caches now have bounded retention. The default keeps the
newest two packages plus the package named by `current`. Cleanup requires a
confirmed running deployment, no pending update and an acknowledged result
queue. The init script retains the persistent cache path when downloads fall
back to RAM, so low space does not permanently prevent cleanup.

Only numeric directories with a valid matching HWID manifest and the expected
three regular payload files are collected. Partial downloads, journal records,
logs, links and unknown entries remain untouched. A synchronized `.gc-*` rename
allows interrupted deletion to finish after restart without recursive deletion.
Set `FWCTLD_CACHE_KEEP=0` to disable collection.

12 init-script cases, journal and catalog tests, four real FIT tests and actual
AArch64 initramfs loading. Publication 60 reported success after reboot on AM625
