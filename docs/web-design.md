# Device Manager Web 设计说明

管理页面服务于嵌入式 Linux 板卡的远程诊断和固件升级。它提供清晰的设备状态入口，所有状态都由已保存的 OTA/SOL 上报计算；没有心跳时，不把设备标为“在线”。

## 参考与取舍

- [OpenBMC Web UI 开发说明](https://github.com/openbmc/docs/blob/master/development/web-ui.md) 将硬件信息、固件更新和网络设置组织为可扩展的管理页面；本项目借鉴模块导航和一致的页面结构。
- [OpenBMC Web UI 风格指南](https://openbmc.github.io/webui-vue/guide/) 强调一致的组件、导航和主题；本项目使用本地 CSS 变量与语义化 HTML，避免在设备调试环境引入前端运行时依赖。
- [Cockpit](https://cockpit-project.org/) 以概况、日志和系统操作组成面向运维人员的工作台；本项目借鉴先看状态、再进入设备和操作页的流程。

这些是交互设计参考。本项目当前不是 BMC，也没有实现 Redfish、KVM 或硬件电源控制；页面只展示已有接口实际提供的数据。

## 页面与数据

| 入口 | 主要内容 | 数据来源 |
| --- | --- | --- |
| 总览 | 设备数量、近五分钟上报、升级成功与历史异常、当前发布和最近活动 | `/api/state`，可用时合并 SOL 设备索引 |
| 设备 | 设备 ID、网络身份、固件 tag/内容 ID、最近结果与事务详情 | `/api/state` 中的设备、升级历史和请求记录 |
| 固件 OTA | 上传、发布、详情、升级历史与发布记录 | `/api/state`、上传和发布接口 |
| 远程日志 SOL | 只读实时流、历史启动、阶段筛选与导出 | `/api/sol/*` |
| 事件与审计 | 固件异常、停发和回退记录 | `/api/state` 中的审计事件 |

所有用户输入和设备上报文本通过 DOM `textContent` 呈现。页面响应式布局保留了窄屏可访问的导航、筛选和表格横向滚动。固件发布仍需要显式点击，上传完成不会自动发布。
